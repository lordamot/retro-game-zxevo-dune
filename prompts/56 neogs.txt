****

The cause is gs_probe (src/gs.asm:199), the "GS detect" line, and it fails on the very first read.

What the probe assumes. It reads the status port $BB 16384 times and calls it "no card" the moment any reading has one of bits 1-6 clear. That assumption came from the emulators. libxpeccy starts pstate at $7E, ZEsarUX uses $7E, and MAME's own NeoGS returns m_status | $7E. An original GS also passes, because it drives only D0 and D7 and the bus pull-ups give the rest. The ZX-MultiSound is the same.

What a NeoGS does. Its FPGA drives all eight data lines on a $BB read. From its zxbus.v (the NeoGS SVN, mirrored at github.com/alfishe/neogs):

  3'b01: dbout <= { data_bit, 6'bXXXXXX, command_bit };

Bits 1-6 are "don't care", so Quartus fills them with whatever logic is cheapest. Most likely that is the same lines as the data-register path, which would make them the bits of the last byte the card sent. The GS port description (GS_PORTS.TXT) only defines D0 and D7 as well. So on a NeoGS, bits 1-6 are not $7E, gs_probe returns carry, and the log says error and no sound. Nothing after it ever runs.

Not confirmed on the machine: exactly what those bits read as. One check settles it. With the NeoGS in, run PRINT IN 187 in BASIC. Anything other than 126, 127, 254 or 255 confirms it.

A second, smaller trap waits behind it. The NeoGS is not reset when the Spectrum is reset (its promo text says so). If an earlier program, or a run of the game reset mid-way, left a byte in the card's latch, status bit 7 stays set. gs_init waits for 65536 readings in a row with status & $81 = 0, and it never gets them: error after about 40 s. gs_init should read $B3 while it waits.

Proposed fix (not made yet):
- gs_probe tests the data flag, which is plain hardware on every GS and needs no ROM. Read $B3, and bit 7 must be 0. Write a byte to $B3, and bit 7 must be 1. Read $B3 again, and it is 0 again. Do that a number of times. With no card it fails every way: a real Evo reads $FF (bit 7 never 0), bin/evo's floating bus reads 0 on the black screen (never 1), and evo-run's gsdead reads $01 (never 1). So make verify's no-card run still tests something.
- gs_init reads $B3 inside its idle wait.
- evo-run gets a NeoGS-like status mode (bits 1-6 not forced to 1), so make verify covers this card.

Say if you want it done.

Sources: MAME's neogs.cpp (github.com/mamedev/mame, src/devices/bus/spectrum/zxbus/neogs.cpp), the NeoGS SVN mirror (github.com/alfishe/neogs: fpga/current/zxbus/zxbus.v, docs/ngs_promo.txt, docs/_old_gs/GS_PORTS.TXT).
