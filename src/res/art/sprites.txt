# sprites.txt - every sprite a Mega Drive Dune II battle draws, for the port.
#
# Written by tools/sega/port_sprites.py from orig/dune2.gen; its docstring
# has the method and `port_sprites.py --check` compares it with the running
# cartridge.  Pictures are in sprites/: RGBA, the battlefield's own colours
# (the 64 at $0A6C90, v*255//7), alpha 0 where nothing is drawn.  Flips are
# baked in and multi-piece sprites flattened: one frame, one picture.
#
# Coordinates: an object's position is its record's y/x words (1/256 of a
# square, so pixel = word >> 3).  A frame's top-left pixel goes at
# position + (dx, dy); dx, dy are pixels and usually negative.

== draw order
# The chain is kept in descending order of layer << 16 | (y + the first
# piece's y), and the VDP draws the first on top: a higher layer covers a
# lower, and within a layer the object further down the screen covers the
# one above it.  (The key adds the object's y in 1/8 pixels to the piece's
# y in pixels, and the chain is only re-sorted when a sprite is made or
# an explosion steps, so a moving unit keeps the place it was made in;
# the port can simply sort by layer, then y.)  The layer is the tag of
# the animation the sprite was made from:
layer $FD  the cursor; $FA the bracket (the pointer is in screen pixels)
layer $14  explosions 0-11, 14, 18, 19; the Sonic Blast
layer $10  Carryall, 'Thopter
layer $0F  Frigate
layer $0C  rockets, Death Hand
layer $0B  bullet, Saboteur, smoke (explosions 9, 10, 15) - also: no house palette
layer $09  the Harvester's dust
layer $08  vehicles: Tank, Siege Tank, Devastator, Sonic Tank, Launcher,
           Deviator, Trike, Raider Trike, Quad, Harvester, MCV
layer $04  foot soldiers
layer $03  explosion 13 (the Sandworm)
layer $02  Sandworm
layer $00  structure markers; corpses (explosions 20-23)
# Within a band of 32 lines the Mega Drive drops pieces of flagged
# sprites when more than 16 sprites or 256 pixels share it ($0011E8);
# the port need not.
